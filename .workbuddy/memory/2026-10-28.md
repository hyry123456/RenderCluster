# 2026-10-28

## 排查：级联阴影「缺一块」（用户报告 cascade 1 有不该被剔除的东西）

### 一、先证明剔除的几何口径是精确的（重要结论，别再往这个方向返工）
平行光的级联是**正交投影，且投影方向 = 光线方向**。正交投影沿光方向不改变光空间 x/y，
所以「簇包围球在光空间 x/y 盒子外」⇔「它投出的阴影也落在盒子外」。
⇒ 6 平面剔除（实际只有 4 个 x/y 平面生效，见下）对平行光级联是**精确**的，
**不可能在盒子内部挖出洞**。盒子内部的阴影缺块一定来自别处。

副产物结论（值得记住）：
- `GeometryUtility.CalculateFrustumPlanes` 是 Gribb-Hartmann，两个 z 平面在
  **reversed-Z** 下都退化成恒真（z∈[0,w] 时 z>=-w 与 z<=+w 恒成立）
  ⇒ 深度方向完全不剔，只在 x/y 剔。这是"安全"的（多画不少画），不是 bug。
- `minTexels` 是**唯一**与相机无关的尺寸型剔除，且 projScale = tileSize*0.5*|proj.m11|，
  实测量级下（2048 tile / 60m 级联 ≈ 34 texel/m）半径 0.05m 以上都不会被剔 ⇒ 基本不起作用。

### 二、真正修掉的 bug：镜像实例（负缩放）的绕序
Unity 内建渲染器对 **det < 0 的 MeshRenderer 会自动翻 culling**，所以 SRP 路径正常；
而我们的 `DrawProceduralIndirect` 没有这层逻辑 ⇒ **Cull Back 会把镜像实例的几何/阴影整块剔掉**。
- 症状完全吻合用户描述：「该是完整的一个东西，却缺了一块」，且**只在 Cluster 路径出现**。
- 修法（烘焙期、运行时零成本）：
  - `ClusterShadowRenderer.Rebuild`：`det < 0` 时索引写 `i0,i2,i1`；
  - `ClusterGBufferRenderer.Rebuild`：同样翻 `_CornerGvid`，并把副切线符号取反
    （反射下 `cross(Rn,Rt) = -R·cross(n,t)`，真实副切线是 `R·b` ⇒ 符号必须反）。

### 三、新增排查开关（都默认关，正常跑零开销）
- `ClusterAssembleAsset.clusterShadowTwoSided` → shader 的 `Cull [_ClusterCullMode]`
  （属性驱动，不必改 shader）。单面片（旗帜/布/细杆/卡片植被）在 Cull Back 下阴影整块消失，
  这是「阴影缺块」最典型的成因之一。打开后光栅化 ×2。
- `ClusterAssembleAsset.clusterShadowStats` → 每 30 帧 `AsyncGPUReadback` 回读 argsBuf，

  都正常但画面仍缺⇒剔除无罪，查深度偏移/投射物登记。
- `Rebuild` 日志新增扫描统计：`扫描 N 个 MeshRenderer → 登记 M 个 mesh`
  `（跳过：disabled / 关投影 / cutout / 无 Mesh）`——阴影缺块第一嫌疑永远是「投射物压根没登记」。
  ⚠️ 特意**保留**「跳过 disabled」的老行为：LODGroup 会把非当前级置 disabled，
  全登记会让多个 LOD 同时投影（重影 + 几何翻倍）。若这个数很大，说明阴影用的是
  「扫描那一刻恰好在看的 LOD」，远处会偏粗（不是缺块）。
- 顺手清掉 `drawMat` 上已不存在的 `_Indices` / `_Visible` 绑定，修正类头注释（还在描述非索引老路径）。

## 追加：排除 Cull Back，锁定「正交级联的 z 范围裁剪」

用户实测：`clusterShadowTwoSided = 1` 之后仍然缺块；且**只有贴近水车时**才断，拉远就完整，太阳没动。
⇒ `Cull Back` 与双面无关（用户的推理正确：剔除模式只跟光方向有关，与相机距离无关）。

**修正我之前的一个错误证明**：我此前断言「级联剔除对平行光是精确的、盒内不可能缺块」——
这只证明了 **x/y**。**沿光轴的 z 范围完全没算**。

正交阴影投影的 z 范围只是 cullingSphere 附近的一条「板」：
投射物 x/y 在盒内、但沿光轴超出这条板 ⇒ **被光栅化器整块裁掉**，
而它落下的阴影在盒内 ⇒ 阴影凭空缺一块。板厚 ∝ 级联尺寸 ⇒「贴近就缺、拉远就好」。
太阳角度低（本场景影子很长）时投射物沿光轴铺得远，最容易触发；水车顶部支臂离地高，正好中招。

**已加修复开关**（默认 1 = 行为完全不变）：
- `ClusterAssembleAsset.clusterShadowDepthPad`（1~8）→ `ClusterShadowRenderer.PadOrthoDepth`
- 实现：正交下 `z_ndc = m22·z + m23`，中心 `= -m23/m22`；`m22 /= pad; m23 /= pad`
  ⇒ 中心不变、斜率变小 ⇒ z 范围扩大 pad 倍。
- **关键**：在 `Shadows.cs` 拿到 `projectionMatrix` 后立刻替换，这样
  「图集采样矩阵 `ConvertToAtlasMatrix(proj*view)`」「cluster 渲染 `worldToClip`」
  「`SetViewProjectionMatrices`（cutout 用）」三处天然一致，不会出现两侧深度约定不符。
- 代价：深度精度按 pad 倍下降（pad=2 ≈ 少 1 bit）+ 极小概率 acne。

**待用户验证**：pad=2（不行再 4）。
- 补上了 ⇒ 确认是 z 裁剪，可以把 pad 定在能覆盖的最小值，或改成"按投射物沿光轴的展开量自适应"。
- 完全没反应 ⇒ 不是 z 裁剪，再把 `clusterForceAll` 打开区分「剔除 vs 绘制/登记」。

## 定案：正交级联深度范围必须由【簇集合自建】（pad=2 实测修复）

**用户的判断正确**：Unity 的级联正交矩阵**只按 `ShadowSplitData.cullingSphere` 拟合**，
沿光轴厚度 ≈ 2×球半径，**完全不看场景里有什么**（不是"看场景里没物体就设小"，而是它压根不看场景）。
Unity 自己唯一的补救是 `light.shadowNearPlane`（`nearPlaneOffset`），只给**近侧**加余量。
我们的投射物是自建的簇集合 ⇒ Unity 不知道分布 ⇒ 必须自家把厚度撑开。

**已实现自动模式**（默认开，`clusterShadowAutoDepth = true`）：
```csharp
need = |dot(sceneSphereCenter - cascadeSphereCenter, light.forward)| + sceneSphereRadius;
have = splitData.cullingSphere.w;              // 原板半厚
pad  = clamp(max(manualPad, need / have), 1, 64);
projectionMatrix = ClusterShadowRenderer.PadOrthoDepth(projectionMatrix, pad);
```
- `sceneSphere` 在 `Rebuild` 里由全部簇的 bounds 求 AABB → 球，`TryGetSceneBounds()` 暴露。
- 必须用 `light.forward`（= 光行进方向），只看 |投影|，符号无所谓。
- **为什么撑大不会引入 acne**：工程的阴影偏置是 `surfaceWS.position + normalBias`，
  normalBias = `surfaceWS.normal * directional.normalBias * _CascadeData[i].y`，**世界空间、投影前应用**
  ⇒ 与 z 范围无关。深度只是按 pad 倍变粗，D32 下几百米仍是亚毫米级。

**教训（写进 MEMORY）**：任何「自建投射物集合」的阴影路径都必须自建三个量：
x/y 盒子、**沿光轴深度范围**、以及偏移量。少一个就会在某个相机距离下凭空缺块。
