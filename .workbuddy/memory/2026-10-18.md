## 续八：Tile-VT 开启后法线错乱 —— 三处 tile 化正确性修复（2026-10-18 00:xx）

用户反馈：页池加大后页表报错消失（确认根因=页数不足）；但 `useTileVT=1 / TilesPerAxis=4` 后**法线错误重现**。
当前配置：`TexturesCount=100, CellCount=4, CellSize=512, paddingSize=0, mipsLevel=3, TilesPerAxis=4`。

### 根因（两处真 bug + 一处质量 bug，均只在 T>1 时出现）
1. **tile 推导没先 Wrap**：`tileUV = baseUV * T` 后 `clamp(0,T-1)`。`baseUV` 已过 `_MainTex_ST`，tiling>1 时 >1，
   所有重复段被压到最后一个 tile → 整片被一张 tile 拉伸铺满，法线方向整体错（albedo 只是"看起来重复"，不易察觉）。
   **修**：`frac(baseUV)` 再 `*T`。5 处全改（FeedbackPass / BRG 两处 / ClusterPBR_Cluster / ClusterInput.GetColor）。
2. **采集侧 padding 映射公式只对 T=1 成立**：原 `(_TileOrigin + uv*_TileScale - pad)/(1-2pad)`。
   漏了"padding 应作用于 cell 局部坐标"这一层，T>1 时每个 tile 内容整体偏移 ≈ padding（mip0 约 8 texel）→
   相邻 tile 拼不回原图 → **接缝处法线/着色不连续**。**修**：`cellUV=(uv-pad)/(1-2pad); uv=origin+cellUV*scale`
   （T=1 时与旧式逐字等价，零回归）。
3. **paddingSize=0**：padding 是"边缘像素外扩"的防串色带，设 0 时每个 cell 最外圈会采到邻块数据。
   **修**：`assemble.asset paddingSize 0→2`（图集 6144²→6336²，5 通道 VRAM 754MB→~802MB，页池不变）。

### 附带修掉的质量 bug（ClusterCore.RequestMinsMap）
- 已驻留 tile 也被塞进 `InitialTextureNode`，而该方法把**所有 mip 槽位**重指到最低级结点 →
  已经升级到高 mip 的 tile 被打回最糊，贴图周期性变模糊；且每帧重复 `DrawTile`。
- **修**：加 `isNewTile[]`，只有本帧新分配的 tile 才绘制 + 写页表；全驻留时连 `SetData` 都跳过。

### 同步
- `README.md` RVT 小节补了 Tile-VT 完整说明（pageId 公式、五处一致、必须 Wrap、padding 映射、改参数要重进 Play）
  与 `CellSize↓+CellCount↑ 显存不变拆更多页` 的调参结论；`已知限制` 里"非业界瓦片级"已删。
- 未做/待观察：若 T=4 仍有接缝，先降 T=2 验证；tile 化后 LOD 公式未随 T 补偿（T 越大越偏向细 mip，页压力×T²），
  若页压力仍大再评估加 `log2(T)` 的 mip 偏置（属于调参，不是正确性问题，勿盲改）。

## 续九：RVT 法线链改用八面体 PackNormal/UnpackNormal（用户"Buffer1 只前两个通道是法线"）

用户反馈：开启 RVT 后法线仍然错，明确"你没用我的 PackNormal 代码，我的 Buffer1 只有前两个是法线"。

### 根因（RVT 法线全链路与用户八面体约定不符，且 8 位钳制）
- `DrawTile.shader` 把 `_Normal0..3` 经 `DecodeNormal`（半球重建）解出完整 float3 切线法线后，
  `Normal = float4(normal, col.w)` 直接写入 `_VirtualNormals`（RenderTextureFormat.Default = 8 位 ARGB32）。
  `normal` 是 [-1,1]，被 8 位无符号格式**钳掉整个负半区** → 法线方向系统性偏移。
- 读取侧三处 `GetNormalTS`（ClusterInput / BRG / Cluster 各一份内联副本）又用 `DecodeNormal`
  （UnpackNormalmapRGorAG 半球重建）**二次解码** → 与 GBuffer RT1 的八面体约定彻底不一致。
- GBuffer 写入/读取侧（`DefferCameraPass` / BRG `PackNormal(worldNormal)` → RT1.xy，照明 `UnpackNormal(rt1.xyz)`）
  本就八面体正确，唯独 RVT→GBuffer 的"法线来源"这一步错了。

### 修复（使 RVT 法线与 GBuffer RT1 同款八面体，且仅用 .xy 两通道）
1. `DrawTile.shader`：`Normal = float4(PackNormal(normalize(normal)), 0.0, col.w);`
   八面体编码存于 .xy（[0,1] 完美适配 8 位 ARGB32，不再丢负半区）；先归一化防全零 blend 出 NaN。
2. 三处 `GetNormalTS`（ClusterInput.hlsl / ClusterPBR_BRG.shader / ClusterPBR_Cluster.shader）+ ClusterInclude.hlsl 副本：
   主法线改 `UnpackNormal(map.xyz)`（八面体重建，去掉二次 `DecodeNormal`）；
   `_NormalScale` 作切线 xy 微调（`normal.xy *= normalScale; normalize`）；
   未驻留 tile 采样清屏黑(0,0)→解码(0,0,-1)背向，按 `map.xy<0.002` 判无效退回切线中值(0,0,1)。
   detail 法线去掉 `UnpackNormal` 之后再 `DecodeNormal` 的二次解码垃圾（仅保留单次 `UnpackNormal(float3(detail.y, detail.w, 1))`）。
3. **未动**：标准路径（`PBRInput.hlsl` 采真实 `_NormalMap`）、`DrawTile` 采源 `_Normal0..3`、`DefferCameraPass`/`SSRPass`/`AmbientOcclusion` 读 RT1，
   这些走真实法线贴图，`DecodeNormal` 半球重建正确，保留。

### 不变量（务必同步）
- **RVT 法线图集 `_VirtualNormals` 与 GBuffer RT1 现统一八面体 .xy 编码**，五处 `GetNormalTS` 副本 + DrawTile 必须保持该约定一致。
- detail 法线 `_VirtualDetail.G/A` 仍是 RVTShader 原样写入的标准法线贴图 xy（既有的 detail 写入/读取约定不匹配问题，因 `_DetailNormal` 门控且用户未报，未动；若日后报 detail 法线错，需把 RVTShader 的 detail 写入也改成八面体或改读取侧为 `DecodeNormal`）。

## 【同日 23:3x】修 TileTable.Dispose 的 MissingReferenceException

## 【同日 23:4x】RVT 法线失效根因：_NormalMap 是 Unity 已知属性名，MPB 绑定被静默跳过（已改名）

**症状**：UseRVT=1 时 albedo 正确（木纹清晰），但法线完全没起伏（表面光滑）。
**诊断**：Normal Debug Mode 8（切线空间法线）显示整片均匀淡蓝紫 = `normalTS` 常量 (0,0,1)，
即 `DecodeNormalSafe` 的守卫 `n.z < 0.02` 被触发并退回 (0,0,1)。

**推导**：`DecodeNormal`（UnpackNormalmapRGorAG）里 `a = A*R`，若采到**纯白 (1,1,1,1)**
（Unity 对「未绑定纹理」的默认返回值），则 `xy = (1,1)` → `z=0` → 守卫触发 → (0,0,1) → 光滑。
模式 3（图集原始样本）此前显示"偏红无纹理"也符合常量特征。

**根因**：`RVTShader` Pass3 用的属性名 **`_NormalMap` 是 Unity 已知属性名**（内置 shader / Shader Graph
都用它），`MaterialPropertyBlock.SetTexture` 对它被特殊处理而**静默失败** → 法线图集采到默认白图。
（`_AlbedoMap` 不是 Unity 属性名，所以 albedo 正常——这解释了"albedo 对、normal 不对"。）

**修复**：改名避开已知属性名
- `RVTShader.shader` Pass3：`TEXTURE2D(_NormalMap)` / `SAMPLE_TEXTURE2D(_NormalMap,...)` → `_RVTNormalSrc`
- `TileTable.cs`：`NormalId = Shader.PropertyToID("_NormalMap")` → `"_RVTNormalSrc"`
- `ClusterObject.ApplyStandardMaterials()` 里的 `_NormalMap` **不动**（那是 DefferStandard 自己的属性名，标准路径正常）

**同类风险（未改，待验证）**：`_EmissionMap` 和 `_DetailMap` 也是 Unity/URP Lit 的已知属性名，
若后续发现 emission/detail 在 RVT 下图集异常，同样改为 `_RVTEmissionSrc` / `_RVTDetailSrc`。
**教训**：给「用 MaterialPropertyBlock 喂贴图」的 shader 起属性名时，一律加工程自有前缀（`_RVT*Src`），
不要用 Unity 内置/常见名，否则静默失败且极难定位（画面只是"没效果"，不报错）。
