### 写侧深度矩阵（新增，隐藏约束，必须与采样侧同源）

### 1. 阴影矩阵：推翻上一轮的手推，改用 unity_MatrixVP

上一轮我写了 `MakeWriteMatrix`（把 proj*view 的 z 行改成 `0.5*w行 - 0.5*z行`），
并把它注释成"已数值验证"。**那个验证是错的**，而且推导方向也错了。已删除。

**正确做法（零推导）**：`Shadows.cs` 里已有 `buffer.SetViewProjectionMatrices(m_cascadeView[i], m_cascadeProj[i])`，
它设置的就是 `unity_MatrixVP`。shader 里直接 `mul(unity_MatrixVP, float4(worldPos,1))`，
与 SRP 路径 `ShadowCaster` pass 的 `TransformWorldToHClip` **完全同一个东西** ⇒ 深度值/方向/裁剪逐位一致。

⚠️ **关键 API 事实（Unity 官方论坛答复，决定性）**：
> "when you pass a projection matrix via `SetMatrix`, you have to call `GL.GetGPUProjectionMatrix`
> on it manually. **Only `CommandBuffer.SetProjectionMatrix` and `.SetViewProjectionMatrices`
> calls it automatically.**"

所以 `SetViewProjectionMatrices` **内部已经自动**做了 GPU 投影转换（含 reversed-Z / y-flip），
`unity_MatrixVP` 拿到的就是 GPU 约定矩阵。**绝不要自己再手推 z 行**（上一轮就是栽在这里）。
（URP 的 `ScriptableRenderer.SetCameraMatrices` 同样是直接 `cmd.SetViewProjectionMatrices(view, proj)`，
不额外调 `GetGPUProjectionMatrix`，可以互相印证。）

数值验证（`.workbuddy/verify_matrix.py`，纯 Python 复刻矩阵运算）：
- `unity_MatrixVP = proj*view` **原样** ⇒ reversed-Z 分支误差 O(1)（差 1.40）⇒ **确认不能用**
- `unity_MatrixVP = GPU约定(proj)*view`（即 `SetViewProjectionMatrices` 的实际输出）
  ⇒ 两个平台分支误差都是 ~1e-16（float 精度）⇒ **一致，可用**

pankaking 也要跟着改回与 `ShadowInput.hlsl` 逐字一致（用 `UNITY_NEAR_CLIP_VALUE` 而不是写死 0/1）：
```hlsl
#if UNITY_REVERSED_Z
    o.pos.z = min(o.pos.z, o.pos.w * UNITY_NEAR_CLIP_VALUE);
#else
    o.pos.z = max(o.pos.z, o.pos.w * UNITY_NEAR_CLIP_VALUE);
#endif
```
⇒ 必须引 core 的平台 API 头拿 `UNITY_REVERSED_Z` / `UNITY_NEAR_CLIP_VALUE`（D3D11/Metal/Vulkan/GL*/GLES #if 链）。

### 4. clusterTargetTexels 的真实含义（用户问的）

**不是顶点数**。每簇顶点数固定 384（128 tri × 3），写死在 shader 的 `VERTS_PER_CLUSTER` 里。
这个字段是"期望一个簇投影到阴影图上占多少 texel"，用于**逐簇 LOD 选择**：
- texelRadius > 该值 ⇒ 簇在图上很粗 ⇒ 只能用最细 LOD
- texelRadius × 2 <= 该值 ⇒ 簇很小 ⇒ 用最粗 LOD
- 中间 ⇒ 选对应级别

默认改成 `0`（= 关闭 LOD 判据，compute 里直接跳过该分支），因为当前只烘 LOD0，判了也没得选。
compute 里加了 `_MaxLod > 1` 的守卫，多级 LOD 时才生效。
