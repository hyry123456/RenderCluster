- **澄清 BRG/簇/虚拟贴图的架构（用户问"是不是 BRG 按簇读、_MainTex_ST 不需要了、怎么定位虚拟贴图"）**：
  - **当前 BRG 不是按簇，是按物体**：`BatchRenderManager.Register` 为每个 `(物体, submesh)` 建一条 BRG batch、`numInstances=1`，是 per-object；"把整个簇作为一个 draw command" 是 Step2 目标（代码注释已写明）。用户脑里的"按簇"是未来形态。
  - **`_MainTex_ST` 仍然需要、而且 BRG 不消除它**：`TransformBaseUV`(ClusterInput.hlsl:95) 用它把 mesh 的 raw UV 变换成纹理坐标，virtual texture 采样仍依赖它。BRG 只是目前**不 per-instance override**它（回退材质默认值），所以画面行为不变。同理 `_MapId`/`_Color`/… 都是回退材质值。
  - **虚拟贴图定位机制**（从 shader 推出）：①mesh 带 UV；②`TransformBaseUV` 应用 `_MainTex_ST` 得物体纹理坐标 `baseUV`；③fragment 里 `uv = baseUV * _VTFeedbackParam.y` 只用于算 **mip 级别**（虚拟贴图 feedback，按屏幕导数选 LOD），不是最终采样坐标；④`_MapId`（当前材质默认）选 `_TextureNodesBuffer[_SumTextureCount*mip + _MapId]` 的 `TextureNode`；⑤`GetColor`：`uv=frac(uv)` 包到 0..1 作为**瓦片内坐标**，`tileBegin + levelPadding.zw*uv` 映射到虚拟图集里该瓦片的像素区，再 `SAMPLE_TEXTURE2D_LOD(_VirtualAlbedo,…)`。即：**物体 UV = 瓦片内坐标；`_MapId` 选哪个瓦片；瓦片在图集里的像素位置由预计算好的 `TextureNode`（CPU 端铺图集时填）给出**。BRG 不需要"定位"——它只提供 `_MapId`（现由材质默认）和几何 UV。
  - **潜在陷阱（待观察）**：当前 `_MapId` 走材质默认 → 同一材质的所有 BRG 实例共享同一 `_MapId` → 同一张虚拟瓦片。要做真·per-cluster 虚拟贴图，`_MapId` 须改为 BRG per-instance metadata 属性并在 `BatchRenderManager.Register` 里注册（扩 metadata 数组），这是 Step2 的内容。
