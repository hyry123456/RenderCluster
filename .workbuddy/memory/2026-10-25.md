# 2026-10-25 Cluster 阴影「无阴影」根因定位与修复

## 最终根因（决定性）
- 数据侧 100% 已证正确：`forceAll` 旁路 + 位置探针（ProbePositions 内核回读 `_Positions[idx]` vs CPU `allPosArray[allIdxArray[t]]`）连续多帧误差 0.0 ⇒ `_Positions` stride/去重映射/缓冲绑定全对；`drawIdxBuf` 索引值即全局顶点号也正确；图集 render target 也正确（Shadows.cs:410 `SetRenderTarget(dirShadowAtlasId)` 后持久）。
- **真凶：`DrawProceduralIndirect` 的 `worldPose` 参数不会可靠地把矩阵喂进自定义 HLSLPROGRAM 的内建 `UNITY_MATRIX_M`**（unity_ObjectToWorld）。见 Unity 官方论坛 "World transform URP + DrawProcedural"：该 draw 下 `UNITY_MATRIX_M` 恒为单位/零矩阵 ⇒ shader 的 `mul(UNITY_MATRIX_M, worldPos)` = 直接把世界坐标当裁剪坐标 ⇒ 远超 `[-w,w]` 全裁光 ⇒ 整张阴影图空、零报错。完美解释「数据全对却啥都不画」。

## 修复（三文件，已 compile_check 零错误零警告）
1. **ClusterShadow.shader**：删 `UNITY_MATRIX_M`，改声明自定义 `float4x4 _ClusterShadowW2C;` 并用 `mul(_ClusterShadowW2C, float4(p,1.0))`。reversed-Z pankaking clamp 保留。
2. **ClusterShadowRenderer.Draw**：新增 `MaterialPropertyBlock m_mpb`（字段），`m_mpb.SetMatrix("_ClusterShadowW2C", worldToClip)` 后随 `DrawProceduralIndirect(..., m_mpb)` 逐 draw 传入。`worldToClip` 走 `Matrix4x4.identity` 占位（shader 已不用内建矩阵）。
3. **Shadows.cs** 绘制循环：`worldToClip = m_cascadeProj[i]*m_cascadeView[i]`（裸 proj*view，与采样侧 `ConvertToAtlasMatrix(proj*view)` 输入逐位一致），注释改为「经 MaterialPropertyBlock 传自定义属性，非 worldPose」。
- 为什么用 MaterialPropertyBlock：per-draw 命令级数据，4 个级联各自独立、互不污染；绝不能用 `drawMat.SetMatrix`/`SetGlobalMatrix`（共享 Material/全局属性在命令执行时才读 ⇒ 4 联全拿到最后一次值）。这是 Unity Answers 帖唯一有效的修法。
