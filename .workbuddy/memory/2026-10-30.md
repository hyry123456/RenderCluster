## Terrain「浮空 / 地面没渲染但阴影还在」排查

症状：Game 视图某块地面（平台下方）看不见，但阴影照常画出来，看起来像浮空。
用户最初怀疑是某个地形没挂上 SRP 组件（TerrainRenderSetup）。

结论（已写入诊断代码，未进 Unity 验证）：
- **「阴影在、GBuffer 不在」= 该物体走了阴影路径却没走簇 GBuffer 可见路径**。
- 场景里 6 个地形 GameObject 全是 prefab 实例，`materialTemplate` 在所有 prefab/scene 都没写；
  全部靠运行期 `TerrainRenderSetup` 注入；`Apply()` 是**全局一次性**给所有地形换材质，
  不可能「只漏一块地形」⇒ 漏网的不是 Terrain 组件，而是**被注册进簇的地面网格（cluster mesh）**。
- 用户在 Cluster 模式下地形本就不投影，但此地面**有阴影** ⇒ 进一步证明它是簇物体（cluster object）。
- 簇 GBuffer 与簇阴影是**两套独立登记**（`ClusterGBufferRenderer.m_entries` vs `ClusterShadowRenderer.meshes`），
  因此会出现「阴影画得出、簇 GBuffer 画不出」。
- 最可能的静默失败：网格 `Register` 成功（被打上 ClusterRenderingLayer 位从 SRP 排除），
  但 `Rebuild` 摊平后**该网格 0 个可见簇**（LOD0/子网格不匹配或 ClusterMeshCache 缺失）⇒ 表面不画、阴影仍在。

已加诊断（安全、无副作用）：
- `TerrainRenderSetup.EnsureAllTerrains()`：每帧兜底，确保所有地形 materialTemplate=TerrainLit，
  并 `LogWarning` 点名漏网地形。
- `ClusterGBufferRenderer.Rebuild`：登记数≠可见簇记录的物体里，对「0 可见簇」的网格 `LogWarning` 点名。

下一步定位法：跑一次 Play，看 Console 是否出现上面两类 `[Terrain]` / `[ClusterGBuffer]` 警告，
警告里的物体名就是漏网对象。若都没有且仍缺块 ⇒ 才是 Hi-Z 误杀（当前 compute 判据为保守式
`tileFar>nearestZ+tol`，理论上不会误剔开阔地面，暂未确认）。

## Cluster 阴影「物体关闭后阴影残留」修复

症状：用户关闭（禁用）某个 ClusterObject 模型后，GBuffer 正确不画它，但簇阴影**还在** ⇒ 浮空阴影。
根因（两路不对称）：
- GBuffer 侧：`ClusterObject.OnEnable/OnDisable` 逐物体 `Register/Unregister` 到
  `ClusterGBufferRenderer.m_entries`（按 Component 索引）→ 禁用立刻生效。
- 阴影侧：`ClusterShadowRenderer` 只在**首次** `Rebuild` 时 `if (meshes.Count==0) ScanScene()`
  扫描一次全场 MeshRenderer，把 mesh+世界矩阵**快照**进 `meshes`/`worlds`，之后不再重扫。
  运行时禁用物体 → 快照永不更新 → 该网格永久留在阴影集合里。

修复（最小改动，复用已验证的 ScanScene）：
- `ClusterShadowRenderer` 新增 `m_rescanNeeded` 标志 + `public void RequestRescan()`（置 dirty+rescan）。
- `Rebuild` 改为：`if (m_rescanNeeded || meshes.Count==0){ Clear(); ScanScene(); m_rescanNeeded=false; }`
  —— Clear 清空旧 meshes/worlds，ScanScene 按当前 activeInHierarchy/enabled 重新登记，禁用物体自然不再进阴影。
- `ClusterObject.OnDisable`：GBuffer `Unregister` 后调 `ClusterShadowRenderer.Instance.RequestRescan()`
  （用 `HasInstance` 守卫，SRP 模式未建实例时 no-op）。
- `ClusterObject.OnEnable`：GBuffer 注册成功（clusterMode!=SRP 分支）后同样 `RequestRescan()`，
  保证重新启用的物体补回阴影集合。
- 代价：每次物体开关触发一次 `FindObjectsByType<MeshRenderer>` 全场景重扫（仅开关帧发生，非逐帧），可接受。
- 编译已通过 `.workbuddy/compile_check.py`（C# 无错无警告）。HLSL 未动，无需验证。
- 已知未修：物体【移动】后 `DropToSRP` 仍会留下旧位置的簇阴影快照（独立的历史问题，用户未报，未动）。

## Cluster 阴影关闭残留（续）：根治「任何物体禁用都清不掉阴影」

用户二次反馈：`terrain_near_01` 关闭后阴影**仍残留**（且它有阴影却没颜色）。说明上一版
`RequestRescan`（只在 `ClusterObject.OnDisable` 触发）**覆盖不全**：`terrain_near_01` 这类
地形网格 / 子物体禁用时并不会走 `ClusterObject` 生命周期 ⇒ 不触发重扫 ⇒ 快照残留。

根因再定位：
- `ClusterShadowRenderer.ScanScene` 扫的是**所有 MeshRenderer**（含地形网格、子物体、非 ClusterObject 普通网格），
  而这些物体的禁用**不**经过 `ClusterObject.OnDisable` ⇒ `RequestRescan` 永不被调用。
- 「阴影在、颜色不在」= 被标了「只由 Cluster 画 GBuffer」(仅 `renderingLayerMask` 的 bit28) 却**没有
  ClusterObject 兜底**：既被 SRP GBuffer 排除（bit28）、又没进簇 GBuffer（没注册）⇒ 完全不可见，
  却被 ScanScene 收进阴影集合投出浮空阴影。
- 注：`terrain_near_01` 经 prefab 追查是**地形网格（MeshRenderer）**，不是 Unity `Terrain` 组件；
  Viking Village 的地形是 mesh，不是 Terrain 系统。

加固修复（在上一版 RequestRescan 之上）：
- `ClusterShadowRenderer` 新增 `m_sources`（每个登记项对应的源 `MeshRenderer`）。`Register(Mesh,Matrix4x4,source)`
  顺带存源；`Clear()` 一并清。
- 新增 `DetectCasterChanges()`：**每帧**在 `Rebuild()` 最开头（早于 `if(!dirty) return`）遍历 `m_sources`，
  任一 `null / !activeInHierarchy / !enabled / shadowCastingMode==Off` ⇒ 置 `m_rescanNeeded+dirty` ⇒ 下次 Build 重扫。
  只做廉价布尔检查（不分配、不 FindObjectsByType），覆盖所有禁用来源（子物体、普通网格、地形网格）。
- `ScanScene` 新增**孤儿簇掩码跳过**：`(mask & ~(1<<ClusterRenderingLayerBit))==0 && GetComponent<ClusterObject>()==null`
  ⇒ 跳过（不投阴影）。正常簇物体有 ClusterObject 不跳过；普通 SRP 物体掩码含 bit0 不跳过。
  直接消除「不可见却投浮空阴影」的最刺眼表现。
- 编译已通过 `.workbuddy/compile_check.py`（无错无警告）。
- 仍待用户进 Unity 验证：① 关闭 terrain_near_01 阴影是否消失；② 若颜色仍不画，Console 会报
  `[ClusterGBuffer] 物体 "terrain_near_01" 已登记但摊平出 0 个可见簇…`（= 该网格 LOD0/子网格/ClusterMeshCache 异常），
  那是 mesh 注册问题，与阴影无关，需另查。

## 原则落地：没有 Cluster 组件 ⇒ 即使在 Cluster 模式也走 SRP

用户最终明确（2026-10-30 12:51）：**物体没挂 Cluster 组件时，就算在 Cluster 模式，SRP 也必须正常启动并渲染它。**
`terrain_near_01`（`terrain_01.fbx` 的子网格 MeshRenderer）卡在残留 `bit28`（Cluster 专用渲染层位）上：
SRP 的 GBuffer 绘制用 `~bit28` 过滤 ⇒ 被 SRP 排除，又没进簇 GBuffer ⇒ 整块消失、仅剩阴影。

修复（两处，C# 编译已通过 .workbuddy/compile_check.py）：
- `ClusterGBufferRenderer`：新增 `ClearOrphanClusterMasks()` —— Play 开始后跑一次，把**没有 ClusterObject 组件却带 bit28**
  的 MeshRenderer 清掉 bit28（退回 SRP）；有 ClusterObject 的不动（掩码归组件管）。在 `Prepare`/`PrepareViewOnly`
  里 `Rebuild()` 之后调用一次（`m_orphanCleaned` 标志，Release 时复位）。
  ⇒ 颜色由 SRP GBuffer 画、阴影由 cluster 阴影画，完全一致；开关物体都正常。
- `ClusterObject.SetRenderingLayerBit` 修 bug：`m_originalRLM` 只**第一次**捕获（`m_rlmCaptured` 标志，禁用→
  重新启用不再覆盖）。原 bug：「禁用还原成 bit28 → 重新启用把 bit28 当原值存下 → 退出 Play 还原出残留 bit28」。
- 这是「颜色缺失」的根治；`ScanScene` 里既有的孤儿簇掩码跳过继续保留作安全网（防清掉 bit28 前那一帧的浮空阴影）。
- 注意：本次未改 Shader——根因是渲染层位（renderingLayerMask）而非 shader，shader 本身正确。
